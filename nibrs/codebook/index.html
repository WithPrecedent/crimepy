    Codebook¶

    This codebook lists every column of the tables that crimepy.nibrs.tables.build makes, in alphabetical order:

    • incidents: one row for each Group "A" incident.
    • offenses: one row for each offense of an incident.
    • victims: one row for each victim of an incident.
    • offenders: one row for each offender of an incident.
    • arrestees: one row for each arrestee of an incident.

    Each table has the columns of its segment, the incident's and agency's columns, and the columns that crimepy adds (see how crimepy converts the data). A column that is in more than one table has one row, and numbered columns that repeat a field (such as offense_1 to offense_10) share a row.

    The description of each column also gives:

    • In: the built tables that have the column.
    • From: the segment of the master files that the column is read from, and where the field is in its records, counted from 1, as in the FBI's record descriptions. Columns that crimepy adds have none.
    • Codes: the codes of the field (as crimepy.nibrs.codes has them) and their labels.

    The type is the column's pandas type:

    • categorical (category): the codes of the master files, which are replaced with their labels when a table is built, unless decode = False is passed. Age codes are kept as codes, since crimepy adds the age in years. A code that is not in the codebook is kept as it is.
    • integer (Int64): a whole number, with pd.NA when it is missing.
    • boolean (boolean): true or false, with pd.NA when it is missing.
    • datetime (datetime64): a date.
    • string (str): text, without the blanks around it.

    The tables that crimepy.nibrs.load returns have the same columns as the segments here. Its other tables (Group "B" arrests, window segments, and the agencies' columns that are not joined to incidents) are described by crimepy.nibrs.layouts.
